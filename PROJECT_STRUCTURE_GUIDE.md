# Project Structure & Folder Detailing Guide

This document provides a comprehensive breakdown of the **Nishad IT Solutions Hybrid Automation Framework**. It outlines the purpose, use, importance, and dependencies for each key directory in the project.

---

## 📂 Root Directory
The top-level container of the project.

### 1. `src/main/java`
*   **Purpose**: Contains the core application logic and reusable utilities.
*   **Use**: Stores classes that are not tests but support the testing infrastructure (Base classes, Utilities).
*   **Importance**: Acts as the foundation of the framework, ensuring code reusability and maintainability.
*   **Content**: `com.nishad.base`, `com.nishad.utils`.
*   **Dependency**: Relies on Selenium, WebDriverManager, and Java core libraries.

### 2. `src/test/java`
*   **Purpose**: The primary location for all test-related code.
*   **Use**: Houses step definitions, hooks, and test runners for Cucumber and TestNG.
*   **Importance**: Separates test logic from infrastructure logic, following standard Maven conventions.
*   **Content**: 
    *   `com.nishad.hooks`: Lifecycle management.
    *   `com.nishad.runners`: Execution orchestration.
    *   `com.nishad.stepdefinitions.api`: Logic for REST API tests.
    *   `com.nishad.stepdefinitions.ui`: Logic for Web UI tests.
    *   `com.nishad.tests.api`: Standard TestNG API tests.
*   **Dependency**: Relies on Cucumber-Java, TestNG, and Rest Assured.

### 3. `src/test/resources`
*   **Purpose**: Stores non-java configuration files and test data.
*   **Use**: Contains feature files, environment properties, and XML suite configurations.
*   **Importance**: Allows for externalizing configurations (like URLs, credentials) without changing code.
*   **Content**: 
    *   `features/api`: Gherkin files for backend testing.
    *   `features/ui`: Gherkin files for frontend testing.
    *   `config.properties`, `testng.xml`.
*   **Dependency**: Used by Cucumber (for features) and TestNG (for suite execution).

### 4. `target/`
*   **Purpose**: The output directory for compiled code and test reports.
*   **Use**: Automatically generated by Maven during the `compile` or `test` phase.
*   **Importance**: Holds the final execution results, logs, and screenshots.
*   **Content**: Compiled `.class` files, Surefire reports, and Cucumber HTML reports.
*   **Dependency**: Generated and managed by Maven.

## 📂 Package Detailing (Internal)

### 📍 `com.nishad.base` (in src/main/java)
*   **Purpose**: Framework initialization logic.
*   **Use**: Contains the `BaseTest` or `DriverManager` class to setup/teardown browsers or API sessions.
*   **Importance**: Ensures every test starts with a clean and consistent environment.
*   **Content**: Driver initialization, common setup methods.

### 📍 `com.nishad.utils` (in src/main/java)
*   **Purpose**: Helper functions for common tasks.
*   **Use**: File reading, Excel handling, JSON parsing, logging, and custom waits.
*   **Importance**: Reduces code duplication across the project.
*   **Content**: `ConfigReader.java`, `Log.java`, `CommonUtils.java`.

### 📍 `com.nishad.hooks` (in src/test/java)
*   **Purpose**: Execution lifecycle management for Cucumber.
*   **Use**: Defines `@Before` and `@After` methods that run before/after each scenario.
*   **Importance**: Handles browser launching, screenshot capture on failure, and cleanup.
*   **Content**: `Hooks.java`.

### 📍 `com.nishad.runners` (in src/test/java)
*   **Purpose**: Orchestrates the execution of Cucumber scenarios.
*   **Use**: Links Feature files with Step Definitions and generates reports.
*   **Importance**: Entry point for running tests via TestNG or Maven.
*   **Content**: `TestRunner.java`.

### 📍 `com.nishad.stepdefinitions` (in src/test/java)
*   **Purpose**: Bridges Gherkin language to Java code.
*   **Use**: Implements the logic for each step defined in `.feature` files.
*   **Importance**: Makes tests readable for non-technical stakeholders.
*   **Content**: `LoginSteps.java`, `ApiSteps.java`, etc.

### 📍 `features/` (in src/test/resources)
*   **Purpose**: Business requirement documentation in Gherkin format.
*   **Use**: Writing user stories and acceptance criteria in `Given`, `When`, `Then` format.
*   **Importance**: Acts as the single source of truth for "What the test does".
*   **Content**: `.feature` files.

## 📄 Key Files

| File | Purpose | Importance |
| :--- | :--- | :--- |
| `pom.xml` | Maven Project Object Model | Manages all dependencies (Selenium, TestNG, etc.) and build plugins. |
| `testng.xml` | Test Suite Configuration | Defines which tests to run, parallel execution settings, and parameters. |
| `config.properties` | Global Environment Settings | Stores variable data like `browser`, `url`, and `timeouts`. |
| `.gitignore` | Version Control Filter | Prevents temporary files (like `/target`) from being pushed to GitHub. |
